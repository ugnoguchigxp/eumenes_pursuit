## 2. 測定を止めているもの（先に片付ける）

1. **計器が `Infinity` のまま。** band-2 の接続エラーで費用不明（`costStatus = "unknown"`）の呼び出しが 3 件残り、計器は設計どおり fail-closed で `Infinity` を返す。このままでは、今後の API 実行は上限チェック（`spend_limit_reached_or_usage_unknown`）で全て止まる。判明分の累計は $39.101。
2. **接続エラーの原因が未確認。** band-2 の 9 件中 3 件が `Error: Connection error.` で終わった。API 側の一時的な問題か、この Mac のネットワークかは切り分けていない。
3. **LARM に届かない。** `PURSUIT_LARM_*` が未設定で、`192.168.0.130:9810` への接続もタイムアウトする。設定 DB 側には `larm.*` の値があるが、live 試験が読む環境変数とは別経路。
4. **環境 B がない。** ablation-1・hz11 の記録の整備（フェーズ 0）と、hz11 の Haiku 比較（フェーズ 1）は、この Mac では実施できない。

1. 費用不明の呼び出し 3 件の扱い。選択肢: (a) 不明分を記録したうえで計器を通常表示に戻す運用を認める、(b) 計器の仕様どおり止めたままにし、band-2 も再開しない、(c) 計器の仕組み自体を見直す（これは新しい変更なので、この草案の範囲外として別途扱う）。
