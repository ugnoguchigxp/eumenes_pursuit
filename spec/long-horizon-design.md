# 長い予算での継続性（一晩回すことの模擬）

作成日: 2026-10-21
状態: 実装済み（policy v5・`bun eval/analyze.ts <run> --horizon`）。live の horizon-1 は未実施。

## 目的

想定の使い方は、ローカル LLM が一晩中回すこと。予算を大きくしたとき、伸びた分で前に進むのか、同じところを回るだけなのかを確かめる。今の予算（試行 40、方針 3）では、未完の追求は予算の 2〜3 割で止まっている。

## 設定

`config/policy.v5.json`（v3 を約 3 倍にしたもの）:

| 項目 | v3 | v5 |
| --- | --- | --- |
| attempts | 40 | 120 |
| strategies | 3 | 6 |
| hypothesesPerStrategy | 3 | 4 |
| stepBacks | 8 | 24 |
| transitions | 300 | 900 |
| wallMs | 30 分 | 90 分 |

他は v3 のまま。

## 測り方（horizon-1）

- 土台は completion-1 の acceptance の腕と同じ構成。腕は v3 と v5。
- 課題:
  - ζ(3) 各 4 回（解けたことのない課題で、長く回すと前に進むか）
  - ln 2 各 6 回（中くらいの課題で、予算が増えると通過が上がるか）
- 指標（台帳から）:
  - 通過、部分点
  - 予算のうち使った割合
  - 前に進んだかどうか
    - 後半の方針で、部品の自己評価の「済み」が前半より増えたか
    - 同じ構成への戻り（方針の本文の類似）
  - 終わり方（断念・停止・予算切れ）と、そのときに残っていた予算
- 費用の見込み: ζ(3) の v5 は 1 回 $0.3 前後で、計 $4〜5。

## 実装（2026-10-21）

- `config/policy.v5.json`: 上の表のとおり。予算以外は v3 と同じ（`eval/test/horizon.test.ts` で検査）。
- `eval/horizon.ts`（台帳だけから計算する純粋関数）と `bun eval/analyze.ts <run> --horizon`:
  - 予算の使用: 実行した試行・方針・一段上へ・手順（revision）・時間（相談の待ちを除く）を、それぞれ予算で割った値（1 で使い切り）と、その最大。
  - 当たった予算: 試行・時間・手順、または評価の実行器の手順数の上限（`--max-steps`）。
  - 前に進んだか: 方針を順に前半と後半に分け（奇数の残りは後半）、部品の自己評価で「済み」の割合の平均を比べた差。自己評価のない方針は数えない。
  - 同じ構成への戻り: 2 つ目以降の方針の本文と、それより前の方針の本文の、文字 bigram の Jaccard 類似度の最大。0.5 以上を戻りと数える（分析だけの定数）。
  - 終わり方と、終わりに残っていた試行予算。
- 評価の実行器の `--max-steps` の既定は 250 で、v5 の手順の上限 900 より小さい。horizon-1 では両方の腕で `--max-steps 1000` を使い、手順の上限が規則層の側で効くようにする。
- LARM の d1 が使えない環境のため、評価用の条件 `E1R`（E3 から判定層だけを除いたもの。規則層と別文脈の振り返りはある）を足した。E3 の土台とは判定層の有無が違うので、completion-1 の数字とは直接比べず、v3 と v5 の腕どうしで比べる。
