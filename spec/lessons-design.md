# 台帳の対比から教訓を作る（経験の再利用）

作成日: 2026-10-20
状態: 実装済み（2026-10-21）。reflect-1 で測る。
参考: google-research/harness2 の experience reflector と、証拠の規律。

## 目的

同じ条件で走らせた追求のうち、解けたものと解けなかったものの分かれ目から、手順の教訓を作る。教訓は、次の課題の追求で、場面に応じて示す。

「回答に行き着く過程を、実装（コード）として持つか、データとして持つか」の、データの側の検証にあたる。

## 対比の取り方

- 単位は、課題 × 条件 × 構成が同じ追求の組。解けたものと解けなかったものの両方があるときだけ対比する。
  - 例: math-6・persist-1 の π² で、2〜4 割が解けている。
- 振り返り役（Sonnet、採点と同じ役）に、両方の軌跡の要約を渡す。要約の中身は、方針・部品・仮説・試行（道具・予測・観測）・判断の列。答えの本文と採点の理由は渡さない。
- 振り返り役の出力:
  - `contrasts`: 分かれ目の一手。各項目に、どちらの追求の何番目の試行・判断かの参照を付ける。
  - `verdict`: 対比ごとに `helped` / `hurt` / `no_effect` / `confounded`。一つの組だけが支える差や、複数の違いが同時にある差は `confounded`。
  - `lesson`: 最大 1 件で、項目は次の三つ。
    - `cue`: どんな場面か。課題の事実ではなく、状況の形。
    - `operation`: そこで何をするか。
    - `evidence`: 対比の参照。
  - 根拠が `confounded` だけなら `NO_ENTRY`。
- 領域の知識を含む教訓（「Niven の多項式を使え」など）は捨てる。判定には harness2 の規則を使う。主題が変わっても意味が通るものだけを、手順の教訓として残す。

## 保存と示し方

- 教訓は評価側のデータ（`eval/lessons/<id>.json`）で、core には入れない。ホストが取り込むときは、ContextStill の経験として渡す想定。
- 示すのは、方針を立てるときと、一段上へ戻るとき。常に出す文面にはしない。示すのは cue と operation だけで、根拠は台帳に残す。
- core の入口は、方針を立てる・振り返る依頼に付ける「ホストからの経験」の文面（`StartInput.experience?: string[]`、最大 5 件・各 300 字）。中身の選び方はホストが持つ。

## 測り方（暗記を避ける）

- 学ぶ元: π²・ζ(3) の軌跡（math-6、persist-1、persist-2）。
- 試す先は学ぶ元と重ならない課題に限る。新しく足す中くらいの難しさの証明の課題を使う（π の無理数性、e の無理数性、√2+√3 の無理数性、log₂3 の無理数性、Σ1/n² = π²/6 など）。
- 腕は二つ。教訓なしと教訓あり。それぞれ各課題 6 回。
- 指標:
  - 照合を通った割合
  - 部分点
  - 断念と停止の内訳
  - 教訓の cue が当たった場面で、operation を実行したか（台帳から分かる範囲で）

## 実装（2026-10-21）

- `eval/reflect.ts`: 同じ課題 × 条件 × 構成の組から、解けたもの（生成層が申告して照合を通ったもの）と解けなかったものを各 2 件とり、振り返り役に渡す。試行ごとの照合の構成は対比に使わない（終わりを決めたのがホストなので）。
  - 振り返り役には、方針・部品・自己評価・仮説・試行（道具・予測・状態）・判断の列だけを渡す。生成層の文に引用された基準 id は伏せる。
  - 教訓を残すのは、領域に依らず（`domainSpecific` が false）、`confounded` でない対比が一つ以上あるときだけ。
  - 残った教訓は、もう一度の呼び出しで、重なりを除いた 3 件以内（各 200 字以内、領域の言葉なし）にまとめる（`merged`）。
- `eval/main.ts --lessons <file>`: `merged` を `StartInput.experience` として渡す。教訓の元の課題で走らせようとしたら拒否する。
- 示す場面: 方針を立てるとき（一段上へ戻ったあとの立て直しを含む）と、仮説を立てるとき。
- 試す先の課題: `h3-pi-irrational`・`h3-e-squared-irrational`・`h3-basel`。
  - √2+√3 は既存の課題（e2）で易しすぎるので外した。
  - Basel は、Fourier・Parseval・無限積を禁じて、中くらいの難しさにした。
  - π の無理数性は π² と手法が近い。手順の教訓でも、近い課題への転移として読む。
- 初回の教訓（`eval/lessons/pi2-claim.json`、persist-2 と completion-1 の π² から）:
  1. 一部の部品が何度も詰まり、局所の修正が続いて全体の草稿が未完成のとき → 詰まりは仮置きか範囲を狭めた形にして、最初から最後まで通しで書き切る。読み返して、本当に欠けた箇所だけを潰す。
  2. 核心の部品が閉じないまま、周辺の整形や検算ばかり進むとき → 欠けている前提を一文で特定して、それを直接解く構成だけを試す。なければ構成要素そのものを作り直す。
  3. 詰まりと診断した部品を解いた草稿があるのに、理由が古い診断のままのとき → 最新の草稿から、部品の主張を一つずつ導き直して状態を更新する。
