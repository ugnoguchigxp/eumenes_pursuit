# Solverの検証情報の受け渡し確認

2026-11-11 · [実装計画](../../solver-verification-feedback-plan.md)

## 変更前後の再現

基準は `59d64a72cfc2ca44fd0bb1622942981e633e66b7`。Eumenes検証用ホストの同じ固定資料・報告・判定を使い、版のダイジェストと終了状態を照合した。根拠不足のケースは、取得済み本文の末尾にある観測を、実際の採点入力から外れた位置に置いた。タイムアウトは採点要求を受け取った固定応答で発生させた。

| ケース | 基準版 | 変更後 |
| --- | --- | --- |
| 成果の不適合 | 合否と自由記述の理由が次の判断に届いた。 | 同じ合否に、対象版、不適合の区分、採点入力に含めた出典範囲と保存記録が付いた。 |
| 採点に使える根拠の不足 | 採点の抜粋に必要な観測がなく不合格。次の判断に資料の欠落を示す構造化情報がなかった。 | 不足した出典IDと、実際に提示した範囲が届いた。元の成果と不合格の判定は保たれた。 |
| 採点のタイムアウト | 検証失敗で未完了になり、検証記録に条件別の結果が残らなかった。 | 対象版、採点入力の識別子、タイムアウトを台帳に記録した。モデルが判定に使った根拠は未確認。既存の再検証で、確定済みの保存を繰り返さず判定を更新できた。 |

不適合と根拠不足は、受入結果の記録直後に中断し、再開後の判断要求に同じ記録が入ることを結合試験で確認した。タイムアウトは既存の終端・再検証経路に従うため、新たなSolver判断は起こらない。再検証に合格した場合も、確定済みの終了状態は保持される。 [新規の結合試験](../../../test/scenario/eumenes-verification-feedback.test.ts)

再現スクリプト、基準と候補の結果、実行ログは [ローカル検証記録](../../../artifacts/solver-verification-feedback-20261111/) に保存した。`baseline-clipped.jsonl` と `candidate-final.jsonl` は同一の固定応答を使った比較結果。

## 部分・結合・通しの結果

コードの複製を固定し、Bun 1.4.4、macOS arm64、実APIを使わない設定で順に検証した。

| 段階 | 結果 |
| --- | --- |
| 部分 | 43件合格。受入条件の照合と、検証失敗時の途中観測の保持を確認した。 [部分試験](../../../artifacts/solver-verification-feedback-20261111/sdk-partial.log) |
| 結合 | 50件合格。3ケースの受け渡し、50区画での方針更新と再開、Evaluator、既存のプロセス復旧を確認した。 [結合試験](../../../artifacts/solver-verification-feedback-20261111/sdk-integration.log) |
| 通し | `bun run verify` は616件合格、12件スキップ、失敗0。性能検査と `bun run build` も通過した。 [通し検証](../../../artifacts/solver-verification-feedback-20261111/sdk-verify.log) · [ビルド](../../../artifacts/solver-verification-feedback-20261111/sdk-build.log) |

最初の通し検証では、受入保護を無効化する試験が対象ファイルを丸ごと置き換え、追加された補助関数の読み込みに失敗した。試験の変更箇所を受入判定関数に限定し、保護を外したときに受入試験の期待値が実際に失敗することを確認した。最終版ではAPIクライアントのタイムアウト例外も固定試験で使用した。
