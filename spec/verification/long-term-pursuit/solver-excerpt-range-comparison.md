# Solverに表示した出典本文の範囲

2026-11-11 · [前回の比較](solver-feedback-regrade-comparison.md)

## 実装と再現

旧試行の `cold-2-feedback` では、`source_read` の12,000字の返却本文に `T12 = -0.7 ℃` があった。8,000字の表示を再構成すると、値と返却開始位置の両方が落ちた。 [旧試行の記録](../../../artifacts/solver-feedback-live-20261111/live/cold-2-feedback/result.json)

Eumenesのサンプルホストは `source_read` と `source_find` の返却に、出典ID、保存本文のSHA-256、返却の開始位置、保存本文の長さ、取得時の打ち切り情報を付ける。ホストは返却本文が保存版の該当箇所と一致することを確認する。Solverへの表示時に、返却範囲と、予算内で実際に表示する範囲を本文とは別の `source` フィールドに出す。範囲は保存本文内のUTF-16オフセットで、終端を含まない。検索で一致しなかった場合の範囲は `null`。元の道具の出力は台帳に保持し、受入検証はその出力を使う。既存の台帳やメタデータを付けないホストは従来の表示を使う。 [ホスト](../../../examples/eumenes/host.ts) · [表示処理](../../../src/domains/generation/source-excerpt.ts) · [結合テスト](../../../test/scenario/eumenes-source-excerpt.test.ts)

## 比較条件

未使用の合成12課題を各2回、両方式で計48枠。全件確認で完了、不明を明記して完了、必須資料が欠けて部分終了の3群に各4課題を割り当てた。固定手順で初稿を保存し、初回の受入検証で不合格になるところまで揃えた。完了可能なうち4課題では、返却本文に正答があるがSolverへの最初の表示には含まれない状態を作った。4課題のうち2題は最新観測、2題は古い観測として表示した。

両方式で修正済み採点器、資料、受入条件、実モデル `gpt-6-luna / medium` と予算を共通にした。前回試験で検証した採点詳細 `criterion.verification` は双方の進捗判断から外した。対照群には旧来の本文表示を渡し、変更群には範囲付きの本文表示と表示終端からの読み進め方を渡した。固定応答の事前確認では24枠が期待した終端に達し、12組で比較開始時点が一致した。 [事前手順](../../../artifacts/solver-excerpt-ranges-20261111/protocol.md) · [事前確認](../../../artifacts/solver-excerpt-ranges-20261111/preflight-check.log) · [共通採点器](../../../eval/solver-comparison/grader.ts)

保存済み本文の再アクセスは、比較開始後に成立した `source_read` と `source_find` の回数。再取得は同一URLへの再アクセス、再保存は比較開始後の回答案保存。Inputは入力総数、CachedはInputのうちキャッシュから読み出した分、Outputは出力総数。固定準備と機械採点は使用量から除いた。

48枠すべてを収録し、比較開始時点は24組で一致した。保存先IDとそれに依存する採点入力のダイジェストを比較から除いた。指定モデルの108要求にAPIエラーやトークン使用量の欠落はなかった。 [実行ログ](../../../artifacts/solver-excerpt-ranges-20261111/live.log)

最初の表示範囲外に正答があった4課題は、両方式とも8/8で正しく完了した。16枠すべてで最初の再アクセスは `source_find` だった。出典の表示終端から続きを読んだ枠はなく、この4課題で全体の再読・検索11→12回を占めた。この群のInputは307,935→305,263、Cachedは80,753→82,317、Outputは21,683→24,816だった。 [全48枠と再アクセスの集計](../../../artifacts/solver-excerpt-ranges-20261111/summary.json)

## 採否と検証

**範囲付き表示を採用する。** 全48枠で公開Markdownが採点対象の回答案と一致し、24組の対比較で採点上の成果物の劣化は0件だった。正しい完了を16/16で維持し、適切な部分終了は7/8から8/8、全体のOutputは2,223トークン減った（3.74%減）。再読・検索は1回増えたため、再読削減の効果は保留する。実装はEumenesのサンプルホストに含まれる。試験は固定資料を使い、初回不合格からの回復を対象とした。出典内検索に使える見出しを依頼文に含むため、検索で位置を絞れない資料で表示終端が有効かはこの比較では測っていない。
